## Highlights

One PR merged and six opened this week, with work focused on the HeadLogic
refactor, safer chain observations and practical operating recipes.

**Operational Excellence (M3).** The HeadLogic refactor grew into a ten-PR
review stack. A new [checked validation step](https://github.com/cardano-scaling/hydra/pull/2952)
makes live transaction, decommit and snapshot state changes consume values
produced by the rule validators, keeping validation separate from signing
and acknowledgement. A further [operation workflow step](https://github.com/cardano-scaling/hydra/pull/2953)
makes the sequence of validating, recording and submitting fanout explicit,
and shares snapshot request context across handlers. Its regression tests
cover recovery after an unexpected chain distribution, acknowledgement
ordering and agreement between live processing and event replay when time
moves backwards. The stack remained under review at the week's end.

Work on [hydra-recipes](https://github.com/cardano-scaling/hydra-recipes)
added [clearer lifecycle instructions and a Preview validation record](https://github.com/cardano-scaling/hydra-recipes/pull/1).
The recorded run exercised a single-party Head on Apple Silicon using a
local Cardano node: opening, restarting before deposit, depositing, making
four transfers, closing and fanning out. Returned layer 1 outputs matched
the final snapshot and the deposited amount. The proposed instructions
explain when deposits become spendable and how to verify returned funds.
A separate [status command](https://github.com/cardano-scaling/hydra-recipes/pull/2)
would show chain sync, Head state, funds and fuel balances, and pending
deposits through `just status`. Both PRs remained open on 22 November.

**Maintenance and DevX (M5).** The
[decrement observation fix](https://github.com/cardano-scaling/hydra/pull/2920)
merged Thursday. Decommitted outputs now carry references to the outputs
created by the layer 1 transaction, starting after the continuing Head
output. Previously, observation paired them with spent input references
and could omit outputs when there were more outputs than inputs. The
regression coverage now checks complete UTxO entries, including their
references, and exercises decommits containing multiple outputs.

The refactor also gained [generated state-machine documentation](https://github.com/cardano-scaling/hydra/pull/2955).
Diagrams are derived from the production Crem types and compositions during
documentation builds, with links back to their source declarations and a
compile-time check for missing or stale registrations. This makes protocol
changes visible in the documentation diff. Reported local validation of
the complete stack included 967 selected node tests, 122 Agda tests, lint,
and the specification and documentation builds. Full Nix validation still
depended on CI because required build-plan dependencies were unavailable
locally.

A [wallet change fix](https://github.com/cardano-scaling/hydra/pull/2957)
opened after a user encountered an underfunded change output. It checks
that the remaining change meets the output's minimum ada requirement and
returns an insufficient-funds error before constructing an invalid
transaction. A regression test covers change just below that minimum.
The PR remained open at the week's end.
